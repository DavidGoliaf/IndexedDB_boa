## 3. Глубокий стресс-тест критических алгоритмов

### 3.1. Алгоритм кодирования `f64` (Float Order-Preserving)
Формула в задании:
```rust
let v = if val == 0.0 { 0.0 } else { val };
let bits = v.to_bits();
let ord = if (bits & (1u64 << 63)) != 0 { !bits } else { bits | (1u64 << 63) };
```
**Проверка граничных значений:**
1. `val = -0.0` -> нормализуется в `+0.0` -> `bits = 0x0000_0000_0000_0000` -> `ord = 0x8000_0000_0000_0000`.
2. `val = +0.0` -> `bits = 0x0000_0000_0000_0000` -> `ord = 0x8000_0000_0000_0000`.
   *(Результат: `-0.0` и `+0.0` кодируются в идентичный байтовый массив `10 80 00 00 00 00 00 00 00`, требование `cmp(-0, 0) == 0` соблюдено).*
3. `val = -Infinity` (`0xFFF0...`) -> знаковый бит 1 -> `ord = !0xFFF0... = 0x000F_FFFF_FFFF_FFFF`.
4. `val = -1.0` (`0xBFF0...`) -> знаковый бит 1 -> `ord = !0xBFF0... = 0x400F_FFFF_FFFF_FFFF`.
5. `val = 1.0` (`0x3FF0...`) -> знаковый бит 0 -> `ord = 0x3FF0... | (1<<63) = 0xBFF0_0000_0000_0000`.
6. `val = +Infinity` (`0x7FF0...`) -> знаковый бит 0 -> `ord = 0x7FF0... | (1<<63) = 0xFFF0_0000_0000_0000`.

**Сравнение порядков байт:**
`0x000F... (-Inf) < 0x400F... (-1.0) < 0x8000... (0.0) < 0xBFF0... (1.0) < 0xFFF0... (+Inf)`.
**Итог:** Порядок байтов математически строго совпадает с естественным порядком вещественных чисел.

---

### 3.2. Алгоритм CESU-8 и экранирование нулей
- Стандартный UTF-8 кодирует суррогаты `U+D800..=U+DFFF` с ошибкой (запрещены стандартом Unicode).
- В `TASK-01` задано независимое побайтовое кодирование каждого UTF-16 code unit (CESU-8):
  - Суррогат `0xD800` попадает в диапазон `0x0800..=0xFFFF` и детерминированно преобразуется в 3 байта `[0xED, 0xA0, 0x80]`.
  - Байт `0x00` экранируется в `[0x00, 0xFF]`, а строка завершается `[0x00, 0x00]`.
- **Проверка порядка префиксов:**
  - Строка `""` кодируется как `[0x30, 0x00, 0x00]`.
  - Строка `"\u0000"` кодируется как `[0x30, 0x00, 0xFF, 0x00, 0x00]`.
  - Так как `0x00 < 0xFF`, строка `""` гарантированно меньше `"\u0000"`.
  - Строка `"\u0000"` (`30 00 FF ...`) гарантированно меньше `"a"` (`30 61 00 00`), так как `0x00 < 0x61`.
**Итог:** Лексикографический порядок байтов CESU-8 с терминатором `0x00 0x00` абсолютно изоморфен посимвольному UTF-16 сравнению спецификации IndexedDB.

### 3.3. Валидация синтаксиса `KeyPath`
Спецификация W3C §2.5 требует, чтобы сегменты пути соответствовали грамматике `IdentifierName` из ECMAScript.
- В `TASK-01` четко запрещены экранирования (`\uXXXX`), которые недопустимы в `keyPath`.
- Заданы правила для первого символа (`ID_Start`, `$`, `_`) и последующих (`ID_Continue`, `$`, `_`, `ZWNJ`, `ZWJ`).
- Для идеального и быстрого соблюдения стандарта Unicode без ручных таблиц рекомендуется добавить в зависимости `boa_idb_core` легковесный крейт `unicode-ident = "1.0"` (см. раздел 4 ниже).

### 3.4. Сериализация циклических графов в Safe Rust (`ScValue`)
В структуре `ScValue` предусмотрена поддержка Memo-ссылок:
- При встрече циклической или разделяемой ссылки сериализатор записывает тег `0x13` + `memo_id`.
- Для явного и безопасного представления таких ссылок в промежуточном дереве `ScValue` без `unsafe` и циклических `Rc` указателей в enum `ScValue` добавлен вариант `ScValue::MemoRef(usize)`.

## 4. Архитектурные рекомендации и дополнения (Включить исполнителю)

При реализации исполнителю необходимо учесть следующие 3 точечных уточнения:

### Уточнение 1. Добавление `unicode-ident` в `workspace.dependencies`
Для валидации `IdentifierName` (правила `ID_Start` / `ID_Continue` из UAX #31) использовать крейт `unicode-ident = "1.0"`:
```toml
# В workspace.dependencies и crates/boa_idb_core/Cargo.toml
unicode-ident = "1.0"
```
Использование в `key/path.rs`:
```rust
fn is_identifier_start(c: char) -> bool {
    c == '$' || c == '_' || unicode_ident::is_xid_start(c)
}

fn is_identifier_continue(c: char) -> bool {
    c == '$' || c == '_' || c == '\u{200C}' || c == '\u{200D}' || unicode_ident::is_xid_continue(c)
}
```

### Уточнение 2. Добавление варианта `ScValue::MemoRef`
В enum `ScValue` (файл `crates/boa_idb_core/src/clone/scvalue.rs`) явно добавить вариант:
```rust
#[derive(Debug, Clone, PartialEq)]
pub enum ScValue {
    // ... все ранее определенные варианты ...
    /// Ссылка на объект в memo-таблице (по индексу 0-based).
    MemoRef(usize),
}
```

### Уточнение 3. Хэшер контрольной суммы
В кодеке `SCF-v1` для вычисления CRC32 использовать `crc32fast::Hasher`:
```rust
let mut hasher = crc32fast::Hasher::new();
hasher.update(&header_and_body);
let checksum = hasher.finalize(); // u32 LE
```
